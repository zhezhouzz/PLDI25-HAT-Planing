\section{Synthesis}\label{sec:synthesis}

To convert the declarative typing rules from \autoref{fig:selected-typing-rules} into an efficient synthesis algorithm, we must address a critical issue, i.e., finding a refined violation property (e.g., $\negSCA'$) from the original one (e.g., $\negSCA$). This refined property has a more sequential form which indicates an specific message order. Moreover, as explained in \autoref{sec:overview}, every symbolic event in $\negSCA'$ needs to align with the handler specification $\Delta$. The declarative subsumption rule \textsc{TSub} allows us to transform the violation property into the correct shape as an oracle, but an efficient algorithm needs to achieve this iteratively.
Our solution is to implement a refinement loop that iteratively shapes the input property into the desired form. This refinement loop focuses on one effect operator (message) application per iteration, adapt both backward and forward synthesis as necessary, refine the violation property by adding new messages before and after current one. After getting a refined violation property, our synthesis algorithm can derive controller program mechanistically. 
On the other hand, \textsc{TSub} also make sure ghost variables and parameters types of function \PAT are strengthen properly before adding into type context, which guarantee there at least one trace is realizable. To address this, our algorithm employs an automata non-emptiness check, which refine the type context directly.

\subsection{Abstract trace}

In the declarative typing rules, the subsumption rule \textsc{TSub} reshapes the automaton into an ``abstract trace'', which is a sequence of concatenated $\lastA \msg{op}{\phi}$. This form allows easy extraction of history and prophecy automata for each symbolic event $\msg{op}{\phi}$. We also use this form in our algorithm, where abstract trace is formally defined as the following.

\begin{definition}[Abstract Trace] An abstract trace $\Pi$ is an automata represented as s-LTL$_f$ in the following special format,
{\small
\begin{alignat*}{2}
\text{\textbf{Abstract Trace}}& \quad &\Pi  ::= \quad & \lastA \msgB{op}{\overline{x}}{\phi} ~|~ \globalA A ~|~ \Pi \seqA \Pi
\end{alignat*}}\noindent
In general, a s-LTL$_f$ formula can be normalized into finite number of abstract traces.
\end{definition}

\begin{example}[Abstract trace] The violation property $\negSCA$ can be normalized into the following abstract trace:
{\footnotesize
  \begin{align*}
\negSCAPi \doteq \allTL \seqA &\lastA \msg{writeRsp}{v = \Code{x} \land st = \true} \seqA \globalA (\neg \msg{writeRsp}{st = \true}) \seqA 
\\&\lastA \msg{readRsp}{v = \Code{y} \land st = \true \land \Code{y} \not= \Code{x}} \seqA \allTL
  \end{align*}}\noindent
which clear states that there is a success $\eff{readRsp}$ with payload different with the last $\eff{writeRsp}$.
\end{example}

\subsection{Synthesis Algorithm}

\begin{algorithm}[t!]
\Params{Ghost variables $\overline{x{:}b}$, and abstract trace $\Pi$ that represent violation property}
\Output{Synthesized controller $e$}
$\Mfw, \Mbw \leftarrow \emptyset, \emptyset$ \tcp*[l]{The message has already preformed forward or backward synthesis}
$\Gamma \leftarrow \overline{x{:}\rawnuot{b}{\top}}$ \tcp*[l]{initialize type context}
% $\Gsender \leftarrow \emptyset$ \tcp*[l]{A global message buffer}
% $\Gchecked \leftarrow \emptyset$ \tcp*[l]{Record all messages that has been checked }
\tcp{If exists a unchecked symbolic event $\msg{op}{\phi}$, and focus on it}
\While{exists $\msgB{op}{\overline{x}}{\phi}$ s.t. $\Pi = \Pi_h \seqA \lastA \msgB{op}{\overline{x}}{\phi} \seqA \Pi_f$ and  $\msgB{op}{\overline{x}}{\phi} \not\in (\Mfw \cap \Mbw)$}{
    $\Gamma \leftarrow \Gamma, \overline{y{:}\rawnuot{b}{\top}}, \_\hasoty{unit}{\phi[x\mapsto y]}$ \tcp*[l]{add qualifier of $\eff{op}$ event into type context}
    \If{$\eff{op} \not\in \Mfw$}{
        $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw) \leftarrow \forward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw)$\;
    }
    \If{$\eff{op} \notin \Mbw$}{
        \lIf{$\eff{op}$ is generatable}{
            $\Mbw \leftarrow \Mbw \cup \{\eff{op}\}$
        }
        \lElse {
        $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw) \leftarrow \backward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw)$
        }
    }
    % $\Gchecked \leftarrow \Gchecked \cup \{\eff{op}\}$ \tcp*[l]{now message $\eff{op}$ is check}
    % $\Gsender \leftarrow \Gsender \setminus \Gchecked$ \tcp*[l]{removed checked message from buffer}
    $\Pi \leftarrow \Pi_h \seqA \lastA \msgA{op}{\overline{y}} \seqA \Pi_f$ \tcp*[l]{refine violation property}
}
$e \leftarrow \S{DeriveTerm}(\Gamma, \Pi)$ \tcp*[l]{derive controller program}
\Return{$e$}\;
    \caption{Synthesis}
    \label{algo:top-syn}
  \end{algorithm}

The top-level synthesis algorithm is shown \autoref{algo:top-syn}, which takes the violation property that normalized as abstract trace as input.
For the convenience of presentation, this algorithm is expressed as a non-deterministic partial function that synthesizes controller programs that indicates a specific message order. Multiple message orders can be the union ($\oplus$) of all possible results of this algorithm. Notably, our tool actually implements a more efficient backtrack search approach. This algorithm indeed presents pseudocode following the intuition in \autoref{fig:intuition-algo}, which refines the violation property $\Pi$ through a refinement loop (lines $3$ - $10$) before deriving the controller program from the refined property (lines $11$). 

\paragraph{Type context} In order to derive the the assumption and assertions over variables, we would like to gather qualifiers that distributed in different symbolic events in the violation property into the type context $\Gamma$, which can be also refined along the refinement loop.
For example, the algorithm on line $4$ in \autoref{algo:top-syn} lifts the local variables $\overline{x}$  and qualifier $\phi$ of a symbolic event $\msgB{op}{\overline{x}}{\phi}$, as a type context $\overline{y{:}\rawnuot{b}{\top}}, \_{:}\nuot{unit}{\phi[\overline{x\mapsto y}]} \vdash \msgB{op}{\overline{x}}{\overline{x = y}}$. We use syntax sugar $\msgA{op}{\overline{y}}$ stand for $\msgB{op}{\overline{x}}{\overline{x = y}}$ in the rest of paper.

\paragraph{Message dependency} The refined property must ensure that each symbolic event has a consistent history and future trace aligned with its \PAT{} in $\Pi$, while avoiding unreliable traces, such as singleton traces like $\lastA\msg{readRsp}{\top}$ without prior requests. Simulating a message buffer with set $B$, as in declarative typing rules, is insufficient without a synthesized program, so our algorithm analyzes message dependencies directly.
Generally, each observable message $\eff{op}$ must be sent by a handler of a preceding message, $\eff{op_{parent}}$, forming a tree-like dependency structure, as in \cite{MessageChain}. The refinement loop reconstructs these trees from selected nodes, refining the violation property into a serialized trace of these dependencies.

\begin{example}[Message dependency] The refined violation property $\negSCA'$ contains three distinct group of messages, that are pairs of requests and corresponding response:
{\footnotesize
  \begin{align*}
  &\lastA \msg{writeReq}{v = \Code{x}} \seqA
   \lastA \msg{writeReq}{v =\Code{y} \land v \not=\Code{x}} \seqA \lastA \msg{readReq}{\top} \seqA \\
    &\lastA \msg{writeRsp}{v = \Code{y} \land st = \true} \seqA
    \lastA \msg{writeRsp}{v = \Code{x} \land st = \true} \seqA
    \lastA \msg{readRsp}{v = \Code{y} \land st = \true \land v \not=
    \Code{x}}
  \end{align*}}\noindent
while the violation property $\negSCAPi$ only two events if different groups, i.e., the last two events.
\end{example}

\paragraph{Property refinement loop} Adapting this new tree-like structure expressing message dependency, for a message, we should explore both its parent and its children, which we called \emph{backward} and \emph{forward} synthesis. Note that, if the handler of message $\eff{op_{parent}}$ sends a new message $\eff{op}$, preform forward synthesis on $\eff{op_{parent}}$ is the same as preform backward synthesis on $\eff{op}$. To avoid apply the synthesis step twice on the same message dependency relation, we introduce two sets $\Mfw$ and $\Mbw$ to record messages that already performed forward or backward synthesis. The intersection of these two sets ($\Mfw \cap \Mbw$) indicates message that is checked to has parent and children messages in abstract trace. The idea is implemented as the refinement loop shown in \autoref{algo:top-syn}. The $\Mfw$ and $\Mbw$ are initialized as empty set (line $1$), then refinement loop starts with an initial type context with all ghost variable with $\top$ qualifier (line $2$). During each iteration, it pick an unchecked symbolic event ($\msg{op}{\phi} \not\in \Mfw \cap \Mbw$ on line $3$) within the abstract trace $\Gamma$, terminating once all symbolic events are check. Within each refinement iteration that focusing on symbolic event $\msgB{op}{\overline{x}}{\phi}$ with its history trace $\Pi_{h}$ and future trace $\Pi_f$, the algorithm first gather its qualifier into type context (line $4$), then try to perform forward (resp., backward) synthesis when current message is not in $\Mfw$ (resp., $\Mbw$). Notably, if a message is generable, it is the ``root'' of the tree-like structure, thus we don't need preform backward synthesis, but just add it in $\Mbw$ for instead (line $8$). Both forward and backward synthesis are endo functions that refines a 6-tuple $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Mfw, \Mbw)$.
Then, refined abstract trace is the concatenation of history trace, current message, and future trace ($\Pi_h \seqA \lastA \msgA{op}{\overline{x}} \seqA \Pi_f$ on line $10$).

\begin{algorithm}[ht!]
% \Params{A 5-tuple $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Gchecked)$ that are type context, history, current, and future automata, as well as checked message set.}
% \Output{Set of refined 5-tuples }
\Procedure{$\forward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Mfw, \Mbw)$}{
    \tcp{Select the \PAT of $\eff{op}$ from handler specification}
    \If{exists $(\eff{op}, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{H}{\msg{op}{\phi}}{F} \bufLR{\overline{\msg{op_i}{\phi_i}}}) \in \Delta$}{
        \tcp{add qualifier of $\eff{op}$ event into type context}
        $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}, \_{:}\nuot{unit}{\phi \land \overline{y = x} }$\;
        $\Pi_h \leftarrow \Pi_h \land H$ \tcp*[l]{merge history automata} 
        $\Pi_f \leftarrow \Pi_f \land F$ \tcp*[l]{merge prophecy automata}
        \tcp{refined type context to make violation property be non-empty}
        \If{exists $\Gamma'$ such that $\Gamma' \sqsubseteq \Gamma$ and $\Gamma' \vdash (\Pi_h \seqA \lastA\msgA{op}{\overline{x}} \seqA \Pi_f) \not\subseteq \neg\allTL$}{
            \tcp{return type context, property, as well as updated forward and backward set}
            \Return{$(\Gamma', \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Mfw \cup \{\eff{op}\}, \Mbw \cup \{\overline{\eff{op_i}}\})$} 
        }
    }
}
\caption{Forward Synthesis}
\label{algo:forward}
\end{algorithm}

\paragraph{Forward and backward synthesis} The forward synthesis subroutine is shown in \autoref{algo:forward}. It first get the \PAT of current message $\eff{op}$ on line $2$, which also indicate the children messages that sent by $\eff{op}$ are $\overline{\eff{op_i}}$. Then the algorithm merge the selected \PAT into the violation property piece-wisely. First, the current message $\eff{op}$ should be aligned, where the type context gathers ghost variables, parameter types, and qualifier on line $3$, also guarantee the payload assumed by violation property are consistent what in \PAT ($\overline{y = x}$). After that, the algorithm merge the history trace with history automata on line $4$, as well as the future trace and prophecy automata (line $5$). In order to guarantee the refined violation property contains at least one realizable trace, we need to check for non-emptiness of the violation property, as previously discussed. Precisely, we make sure the violation property $\Pi_h \seqA \lastA\msgA{op}{\overline{x}} \seqA \Pi_f$ is not included by empty set, i.e., $\not\subseteq \neg \allTL$).
In fact, under different substitution $\sigma \in \denot{\Gamma}$, the violation property will also have different denotation. We would like to find an refined type context $\Gamma'$ that is only denoted with substitution guarantee the non-emptiness. This idea is implement on line $6$, where $\Gamma' \sqsubseteq \Gamma$ as the following
{\small\begin{align*}
    \Gamma' \sqsubseteq \Gamma \doteq \denot{\Gamma'} \subseteq \denot{\Gamma} \land \denot{\Gamma'} \not=\emptyset
\end{align*}}\noindent
Here, we apply the abduction inference technical used by existing works\cite{?}.
Finally, the algorithm returns the refined type context, property, as well as forward and backward set on line $7$. The forward set additional contains parent message $\eff{op}$, backward set additional contains children message $\overline{\eff{op_i}}$.

\begin{algorithm}[ht!]
\Procedure{$\backward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Mfw, \Mbw)$}{
    \tcp{Select the \PAT of some $\eff{op_{parent}}$ from handler specification, who sends message $\eff{op}$}
    \If{$(\eff{op_{parent}}, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{H}{\msg{op_{parent}}{\phi}}{F_1 \seqA \lastA \msgB{op}{\overline{x'}}{\phi'} \seqA F_2}\bufLR{\msgB{op}{\overline{x'}}{\phi'} \cup \overline{\msg{op_i}{\phi_i}}}) \in \Delta$}{
        \tcp{add qualifier of $\eff{op_{parent}}$ and $\eff{op}$ event into type context}
        $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}, \_{:}\nuot{unit}{\phi \land \phi'\overline{[x'\mapsto x]}}$\;
        $\Pi_h \leftarrow \Pi_h \land (H \seqA \lastA \msgA{op_{parent}}{\overline{y}} \seqA F_1)$ \tcp*[l]{merge history automata} 
        $\Pi_f \leftarrow \Pi_f \land F_2$ \tcp*[l]{merge prophecy automata}
        \tcp{refined type context to make violation property be non-empty}
        \If{exists $\Gamma'$ such that $\Gamma' \sqsubseteq \Gamma$ and $\Gamma \vdash (\Pi_h \seqA \lastA\msgA{op}{\overline{x}} \seqA \Pi_f) \not\subseteq \neg\allTL$}{
        \tcp{return type context, property, as well as updated forward and backward set}
            \Return{$(\Gamma', \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Mfw \cup \{\eff{op_{parent}}\}, \Mbw \cup \{\eff{op}, \overline{\eff{op_i}}\})$}\;
        }
    }
}
\caption{Backward Synthesis}
\label{algo:backward}
\end{algorithm}

The backward synthesis subroutine is shown in \autoref{algo:backward}, which is similar as forward synthesis but explore the message dependency from children messages back to parent message. This reversed direction leads several differences. We pick a message $\eff{op_{parent}}$ that will send $\eff{op}$ instead of message $\eff{op}$ on line $2$. Then, the violation property needs to align the current message $\eff{op}$ with the $\eff{op}$ in the prophecy automata of \PAT of $\eff{op_{parent}}$, instead of its current automata, as shown below
{\small\begin{align*}
    \underbrace{ \effL H \effR \effL \lastA \msg{op_{parent}}{\phi} \effR  \effL F_1 }_\texttt{actual history}
    \seqA 
    \underbrace{ \lastA \msgB{op}{\overline{x'}}{\phi'} }_\texttt{actual current }
    \seqA
    \underbrace{ F_2 \effR }_\texttt{actual prophecy}
\end{align*}}\noindent
which changes the merge procedure (line $3$ - $5$) in backward synthesis. Also, the forward set adds the parent message $\eff{op_{parent}}$ instead of current one, and backward set adds all children message ($\{\eff{op}, \overline{\eff{op_i}}\}$).

\begin{example} To demonstrate the refinement of the violation property $\negSCA$ into $\negSCA'$ in our motivating example:
{\footnotesize\begin{align*}
\Gamma \equiv\;& \Code{x}\hasoty{int}{\top}, \Code{y}\hasoty{int}{\top} \quad \Mfw \equiv \emptyset \quad \Mbw \equiv \emptyset
\\B \equiv\;& \allTL \seqA \lastA \msg{writeRsp}{v = \Code{x} \land st} \seqA \globalA \neg \msg{writeRsp}{st} \seqA \lastA\msg{readRsp}{v = \Code{y} \land st \land \Code{y} \not= \Code{x}} \seqA \allTL
\tag{before iteration $1$}
\end{align*}}\noindent
In the first iteration, our algorithm focus on message $\eff{readRsp}$. Our algorithm perform forward synthesis since this message is not record in $\Mfw$. As specified by $\Delta$, no additional messages are sent by the handler of $\eff{readRsp}$, thus the violation property doesn't changed. Then we perform backward synthesis since $\eff{readRsp}$ is not generatable. There are two types in by $\Delta$ that has prophecy automata contains $\eff{readRsp}$:
{\footnotesize\begin{align*}
&\Code{x}\hasnty{int}\garr \rg{\finalA \msg{writeReq}{v = \Code{x}} \land \neg\nextA\finalA\msg{writeReq}{\top}}{\lastA\msg{readReq}{\top}}{\finalA\msg{readRsp}{v = \Code{x} \land st = \true}} \tag{$\tau_1$}
\\& \rg{\neg\finalA
                 \msg{writeRsp}{\top}}{\lastA\msg{readReq}{\top}}{\finalA\msg{readRsp}{st
                 = \false}} \tag{$\tau_2$}
\end{align*}}\noindent
The $\tau_2$ assume the $\eff{readRsp}$ message has a false status as payload, which is conflict with violation property and cannot pass the non-emptiness check. On the other hand, if we choose $\tau_1$, then we will perform the following piecewise merge, which leads the following result:
{\footnotesize\begin{align*}
\Gamma \equiv\;& \Code{x}\hasoty{int}{\top}, \Code{y}\hasoty{int}{v \not= x}, \Code{s_0}\hasoty{bool}{v = \true} \quad \Mfw \equiv \{\eff{readRsp}, \eff{readReq}\} \quad \Mbw \equiv \{\eff{readRsp}\}
\\B \equiv\;& \allTL \seqA \lastA\msg{writeReq}{v =\Code{y}} \seqA \globalA \neg \msg{writeReq}{\top} \seqA \lastA\msgA{readReq}{y} \seqA \allTL \seqA 
\\&\lastA\msg{writeRsp}{v = \Code{x} \land st = \true} \seqA \globalA \neg \msg{writeRsp}{st} \seqA \lastA\msgA{readRsp}{y,s_0} \seqA \allTL \tag{after iteration $1$}
\end{align*}}\noindent
where we know there is a new symbolic event $\msg{writeReq}{v =\Code{y}}$ happens before $\eff{readReq}$, which is required by $\tau_2$. The rest of refinement steps can be found in \techreport{}.
\end{example}

\begin{theorem}\label{theorem:algo-sound}[Synthesis Algorithm Soundness]
The controller synthesized by the algorithm is also type safe with respect our declaritive typing rules.
\end{theorem}
