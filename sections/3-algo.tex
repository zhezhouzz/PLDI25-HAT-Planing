\section{Synthesis}
\label{sec:synthesis}

\begin{figure}[ht!]
  \centering
  \includegraphics[width=0.84\linewidth]{figures/syn-gen.drawio.png}
  \caption{\name{}'s high-level test generator synthesis algorithm}
  \label{fig:syn-gen}

Given an SRE $A$ describing some property of a black box test system
under test, \autoref{theorem:sound} ensures that a well-typed test
generator program $\emptyset \vdash e : \uhat{\epsilon}{\Unit}{F}$
must be able to produce \emph{every} trace $\alpha$ that is consistent
with both $F$ and $A$, i.e. $\alpha \in F \land A$. Thus, the
high-level goal of our synthesis procedure is to find a generator that
a) uses effectful operators in a way that is consistent with the
temporal and data-dependency constraints captured by their
specifications in $\Delta$, and b) has a future automata has a
meaningful overlap with $A$. Our synthesis algorithm simultaneously
solves both problems by first using a loop, depicted in
\autoref{fig:syn-gen}, to iteratively \emph{refine} a target SRE into
one that satisfies all the constraints of the operators appearing in
it. Each iteration of this loop targets a single event, adding events
before and after that event so that its dependences are satisfied, so
that the corresponding operator at that point in the synthesized
program is well-typed. Our loop also employs an regex non-emptiness
check to ensure it represents a generator that produces at least one
feasible trace. After the refinement loop has finished, a
corresponding well-typed generator program can be mechanically
extracted using the refined property as a template.

\subsection{Abstract Traces}

Our refinement loops operates over SREs that have been normalized into
sets of sequences of abstract events $\msg{op}{\phi}$ and Kleene
stars. This normal form makes it easy for our algorithm to identify
the events that must precede and follow each event $\msg{op}{\phi}$ in
an SRE. \BD{There's a mismatch here-- our algorithms operate over a
  \emph{single} abstract trace, but our normalization procedure
  produces sets of traces? }

\begin{definition}[Abstract Trace] An abstract trace $\Pi$ is a SRE
  without union and top-level Kleene star, defined by the following
  grammar \BD{Why is it $A*$ and not $\Pi*$? An example of a
    non-normalized SRE and its normalized form would be very
    helpful}: %
  {
    \begin{alignat*}{2}
      \text{\textbf{Abstract Trace}} \quad \Pi ::= \quad & \epsilon
      ~|~ \msg{op}{\phi} ~|~ \Pi \seqA \Pi ~|~ A^*
    \end{alignat*}} \noindent Every SRE can be normalized into a
  finite set of abstract traces.\footnote{The definition of our SRE
    normalization procedure is provided in the \techreport{}.}
\end{definition}

\begin{example}[Potential Violation of Read Atomicity]
  Assume we want to probe whether a system that provides asynchronous
  $\eff{read}$ and $\eff{write}$ operations ensures read
  atomicity. Using the variable $x$ as a stand-in for a concrete value
  returned by $\eff{read}$, we can capture this property is captured
  with the following abstract trace:
\begin{align*}
  \allA \msg{\respEvtName{writeRsp}}{v \not= x}(\anyA \setminus \msgC{\respEvtName{writeRsp}})^* \msg{\respEvtName{read}}{v = x} \tag{$\Pi_\Code{RA}$}\label{prop:global}
\end{align*}
\end{example}

\subsection{Synthesis Algorithm}

\setlength{\textfloatsep}{4pt}
\begin{algorithm}[t!]
  \Params{Ghost variables $\overline{x{:}b}$, operator context
    $\Delta$, and abstract trace $\Pi$}%
  \Output{Generator $e$, such that
    $\Gamma \vdash e : \uhat{\epsilon}{\Unit}{\Pi'} \land \Gamma
    \vdash \Pi' \subseteq \Pi$} %
  $\Gamma \leftarrow \overline{x{:}\urt{b}{\top}}$ \tcp*[l]{initialize
    type context} \While(\tcp*[h]{an event that needs to be
    refined}){exists $\msg{op}{\phi}$ s.t.
    $\Pi = \Pi_h \seqA \msg{op}{\phi} \seqA \Pi_f$}{
    $(\Gamma, \Pi) \leftarrow \refine(\Delta, \Gamma, \Pi_h,
    \msg{op}{\phi}, \Pi_f)$ }
% $(\Gamma, \Pi) \leftarrow \synRec(\Gamma, M, \Pi)$ \tcp*[l]{synthesize loop}
\Return{$\derive(\Gamma, \Pi)$} \tcp*[l]{synthesize recursions and derive generator program}
\caption{Synthesis}
\label{algo:top-syn}
\end{algorithm}

Our top-level synthesis algorithm is shown in \autoref{algo:top-syn}.
Given an abstract trace $\Pi$ that uses a set of ghost variables
$\overline{x{:}b}$, this algorithm synthesizes a well-typed $\DSL{}$
generator. The algorithm maintains a typing context $\Gamma$ that
includes all variables appearing in the $\Pi$ \BD{Why?}; this
initially consists of $\overline{x{:}b}$ (line $1$).  The algorithm
first uses a refinement loop (lines $2$ - $3$) to refine the input
abstract trace $\Pi$ into one consistent with the operator context
$\Delta$, and then uses the resulting trace to derive the final
(recursive) generator (line $4$). Each iteration of this loop
nondeterministically chooses a target event in the current abstract
trace (line $2$) whose dependencies are not satisfied \BD{The current
  loop guard does not discuss consistency at all-- need to fix} and
then uses the $\refine$ subroutine to insert the required operations
before and after the target event \BD{Are we still doing anything
  after}.  Different choices may result in different event orders, and
some of these choices may cause the algorithm to fail. Our
implementation resolves this nondeterminism in the algorithm via an
efficient backtracking search procedure that takes the union of all
successful runs in order to capture different orderings. \BD{How does
  backtracking work, what happens when refine fails, how do we build a

  \Gamma \equiv\; x{:}\urt{\Int}{\top} \quad

Assume the first iteration targets the observable event $\msg{readRsp}{v = x}$ (colored blue). The algorithm invokes abstract trace refinement backwardly to locate the corresponding request event (i.e., $\eff{readReq}$) in history. The retrieved type of $\eff{readRsp}$ is shown below, which requires that there is a write response event and read request event that has happened before:
\vspace{-.4cm} \par\nobreak{\footnotesize %
\begin{align*}

\end{align*}}\noindent
During the merging of abstract traces, the algorithm finds that the $\msg{writeRsp}{i\;x}$ event in the type cannot be aligned with the $\msg{writeRsp}{v \not= x}$ event, nor inserted between it and $\msg{readRsp}{v = x}$ in the abstract trace, since they have conflicting qualifiers, which will be rejected by the non-emptiness check. Kleene stars ($A^*$) in abstract traces are interpreted as recursion
points. The synthesis algorithm $\derive$ non-deterministically either
(i) generates a sequential program by eliminating all ghost events and
the Kleene stars \footnote{The definition of $\derive$ is provided in
  the \techreport{}.}, or (ii) synthesizes a recursive program by
expanding the Kleene star using recursion. We employ a template-based
strategy, in which algorithm match the given abstract trace with a
template $T$, together with abstract traces for the recursion body
($\Pi_{\Code{rec}}$), as well as its associated history ($\Pi_h$) and
future ($\Pi_f$) traces. According to \textsc{TFixInd}, the algorithm
unrolls the recursive body up to a bounded depth and invokes
refinement loop (lines 2-3 in \autoref{algo:top-syn}) to ensure that
the unrolled abstract traces are well-typed. The synthesized programs
for these three traces are then composed to instantiate the
placeholders in the recursive template.

\begin{example}[Recursion Template]
  A representative template is a non-deterministic loop, whose form is
  $T = \boxed{e_\Code{h}};\zlet{f}{\mykw{fix}\ f.\lambda ().\
    \boxed{e_\Code{rec}};\ (()\oplus f())}{f\;()};\boxed{e_\Code{f}}$,
  allowing $A^*$ in the abstract trace to be matched. For instance,
  consider the refinement of the abstract trace $\Pi_\Code{RA}$:
  \vspace{-.4cm} \par\nobreak {\small %
    \begin{align*} &\Pi_\Code{refined} \equiv\;
                     \underbrace{\epsilon}_\text{history trace}
                     \underbrace{\allA}_\text{placeholder of previous iterations}
                     \underbrace{\msgA{writeReq}{i\;x}\allA\msgA{writeRsp}{i\;x}
                     ... \msgA{readRsp}{i\;x}}_\text{one iteration of recursion}
                     \underbrace{\epsilon}_\text{future trace}
    \end{align*}} %
  \noindent
  Here, $\Pi_\Code{refined}$ corresponds to the traces generated by a
  single iteration of Example~\ref{ex:read-atomicity}. The template
  thus assigns $\Pi_{\Code{rec}} = \Pi_\Code{refined}$, with $\Pi_h$
  and $\Pi_f$ as empty traces (i.e., $\epsilon$). The synthesizer
  refines the abstract trace for $i$-fold recursion unrolling (i.e.,
  $\Pi_h\Pi_{\Code{rec}} \ldots \Pi_{\Code{rec}}\Pi_f$) to guarantee
  that multiple unfoldings remain well-typed. The final recursive
  program is assembled by composing synthesized programs from these
  traces to populate the template placeholders, thereby yielding
  exactly the recursive function in Example~\ref{ex:read-atomicity}.
\end{example}

\begin{theorem}[Synthesis is Sound]
  \label{theorem:algo-sound}
  The generator synthesized by the algorithm is type-safe with
  respect to our declarative typing rules.
\end{theorem}
