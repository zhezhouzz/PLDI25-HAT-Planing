\section{Synthesis}\label{sec:synthesis}

To convert the declarative typing rules given in
\autoref{fig:selected-typing-rules} into an efficient synthesis
algorithm, we must address a critical issue, i.e., finding a refined
violation property (e.g., $\negSCA'$) from the original (e.g.,
$\negSCA$).  Recall that this refined property has a more sequential
form that indicates a specific message order that the synthesized
controller is obligated to follow. Moreover, as explained in
\autoref{sec:overview}, every symbolic event in $\negSCA'$ needs to
align with the handler specification $\Delta$, i.e., temporal and
data-dependency constraints found in $\Delta$ must be manifest in
$\negSCA'$.

The declarative subsumption rule \textsc{TSub} serves as an oracle to
allow us to transform a violation property into the correct shape, but
an efficient algorithm needs to achieve this iteratively.  Our
solution is to thus implement a refinement loop that shapes the input
property into the desired form as depicted in
\autoref{fig:intuition-algo}. The loop focuses on one effect operator
(message) application per iteration, adapting both backward and
forward synthesis as necessary, refining the violation property by
adding new messages before and after the current one.  After
refinement, the synthesis algorithm can derive the controller program
mecanically.  Note that declarative typing rules always assume \PAT{}s
are well-formed, guaranteeing that there is at least one trace that is
realizable. To address this, our algorithm also employs an automata
non-emptiness check.

\subsection{Abstract trace}

\textsc{TSub} reshapes an automaton into an \emph{abstract trace},
a sequence of concatenated $\lastA \msg{op}{\phi}$ events. This form
allows easy extraction of history and prophecy automata for each
symbolic event $\msg{op}{\phi}$. We also use this form in our
algorithm.

\begin{definition}[Abstract Trace] An abstract trace $\Pi$ is an automata represented as an s-LTL$_f$ formula
  defined by the grammar:
{\small
\begin{alignat*}{2}
\text{\textbf{Abstract Trace}}& \quad &\Pi  ::= \quad & \lastA \msgB{op}{\overline{x}}{\phi} ~|~ \globalA A ~|~ \Pi \seqA \Pi
\end{alignat*}}\noindent
In general, any arbitrary s-LTL$_f$ formula can be normalized into a finite set of abstract traces.
\end{definition}

\begin{example}[Abstract trace] The violation property $\negSCA$ can be normalized into the following abstract trace:
{\footnotesize
  \begin{align*}
\negSCAPi \doteq \allTL \seqA &\lastA \msg{writeRsp}{v = \Code{x} \land st = \true} \seqA \globalA (\neg \msg{writeRsp}{st = \true}) \seqA 
\\&\lastA \msg{readRsp}{v = \Code{y} \land st = \true \land \Code{y} \not= \Code{x}} \seqA \allTL
  \end{align*}}\noindent
which describes an execution in our running example in which a successful $\eff{readRsp}$
message carries a value different from the last handled $\eff{writeRsp}$.
\end{example}

\subsection{Synthesis Algorithm}

\begin{algorithm}[t!]
\Params{Ghost variables $\overline{x{:}b}$, and abstract trace $\Pi$ that represent violation property}
\Output{Synthesized controller $e$}
$\Mfw, \Mbw \leftarrow \emptyset, \emptyset$ \tcp*[l]{}
$\Gamma \leftarrow \overline{x{:}\rawnuot{b}{\top}}$ \tcp*[l]{initialize type context}
% $\Gsender \leftarrow \emptyset$ \tcp*[l]{A global message buffer}
% $\Gchecked \leftarrow \emptyset$ \tcp*[l]{ }
\tcp{Pick a previously unexamined symbolic event $\msg{op}{\phi}$}
\While{exists $\msgB{op}{\overline{x}}{\phi}$ s.t. $\Pi = \Pi_h \seqA \lastA \msgB{op}{\overline{x}}{\phi} \seqA \Pi_f$ and  $\msgB{op}{\overline{x}}{\phi} \not\in (\Mfw \cap \Mbw)$}{
    % \tcp*[l]{add qualifier of $\eff{op}$ event into type context, $z$ fresh}
    % $\Gamma \leftarrow \Gamma, \overline{y\,{:}\rawnuot{b}{\top}},\, z\,\hasoty{unit}{\phi[x\mapsto y]}$\;
    \If{$\eff{op} \not\in \Mfw$}{
        $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw) \leftarrow \forward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw)$\;
    }
    \If{$\eff{op} \notin \Mbw$}{
        \lIf{$\GEN(\eff{op})$}{
            $\Mbw \leftarrow \Mbw \cup \{\eff{op}\}$
        }
        \lElse {
        $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw) \leftarrow \backward(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{y}}, \Pi_f, \Mfw, \Mbw)$
        }
    }
    % $\Gchecked \leftarrow \Gchecked \cup \{\eff{op}\}$ \tcp*[l]{now message $\eff{op}$ is check}
    % $\Gsender \leftarrow \Gsender \setminus \Gchecked$ \tcp*[l]{removed checked message from buffer}
    $\Pi \leftarrow \Pi_h \seqA \lastA \msgA{op}{\overline{y}} \seqA \Pi_f$ \tcp*[l]{refine violation property}
}
$e \leftarrow \S{DeriveTerm}(\Gamma, \Pi)$ \tcp*[l]{derive controller program}
\Return{$e$}\;
    \caption{Synthesis}
    \label{algo:top-syn}
  \end{algorithm}

The top-level synthesis algorithm is shown \autoref{algo:top-syn}.  It
takes a violation property normalized as an abstract trace as input
and returns a synthesized controller expressed in $\DSL$.  For
convenience of presentation, this algorithm is expressed as a
non-deterministic partial function that synthesizes a controller
program that mandates a specific message order.  Multiple message
orders can be described as the union of all possible results of this
algorithm.  Our implementation manifests the non-determinism in the
algorithm via an efficient backtracking search procedure.  The
algorithm follows the structure given in \autoref{fig:intuition-algo},
refining a violation property $\Pi$ through a refinement loop (lines
$3$ - $9$) before deriving the controller program from the refined
property (lines $10$).

\paragraph{Message dependency} The refined violation
property must ensure that each symbolic event has a consistent history
and future trace aligned with its \PAT{} in $\Pi$, while avoiding
unrealizable traces, such as singleton traces like
$\lastA\msg{readRsp}{\top}$. Simulating a message buffer $B$, as we
did in the declarative typing rules, is insufficient without a
synthesized program, so our algorithm analyzes message dependencies
directly.  Intuitively, each observable effectful operation $\eff{op}$
must be emitted by a handler of a preceding message whose operation is
$\eff{op_{parent}}$, forming a tree-like dependency structure, as in
\cite{MessageChain}. The refinement loop reconstructs these trees from
selected nodes, refining the violation property into a serialized
trace of these dependencies.

\begin{example}[Message dependency] The refined violation property $\negSCA'$ contains three distinct
  group of messages, grouped into pairs of requests and corresponding responses:
{\footnotesize
  \begin{align*}
  &\lastA \msg{writeReq}{v = \Code{x}} \seqA
   \lastA \msg{writeReq}{v =\Code{y} \land v \not=\Code{x}} \seqA \lastA \msg{readReq}{\top} \seqA \\
    &\lastA \msg{writeRsp}{v = \Code{y} \land st = \true} \seqA
    \lastA \msg{writeRsp}{v = \Code{x} \land st = \true} \seqA
    \lastA \msg{readRsp}{v = \Code{y} \land st = \true \land v \not=
    \Code{x}}
  \end{align*}}\noindent
In contrast,  the original property $\negSCAPi$ defines only one distinct group of two events,
namely the last two events comprising $\negSCA'$.
\end{example}

\paragraph{Property refinement loop} Exploiting message dependencies
requires us to explore parent as well as children dependencies of a
symbolic event occurring in an abstract trace; the former constitutes
the \emph{backward} synthesis phase of the algorithm, while the latter
is subsumed by a \emph{forward} synthesis pass.  Note that if a
message handler for operation $\eff{op_{parent}}$ emits a new message
for operation $\eff{op}$, performing forward synthesis on an event
with operation $\eff{op_{parent}}$ is the same as performing backward
synthesis on $\eff{op}$. To avoid applying the synthesis step
repeatedly on the same dependency, we introduce two sets $\Mfw$ and
$\Mbw$ to record events whose children or parent dependencies have
been synthesized into their message counterpart, resp.  The
intersection of these two sets ($\Mfw \cap \Mbw$) are thus events
whose dependencies are fully accounted for by the synthesis algorithm.


The refinement loop shown in \autoref{algo:top-syn} initializes $\Mfw$
and $\Mbw$ at line $1$, and starts with an initial type context with
all ghost variables having qualifier $\top$ (line $2$). During each
iteration, an unchecked symbolic event is picked ($\msg{op}{\phi}
\not\in \Mfw \cap \Mbw$ (line $3$) within the abstract trace $\Gamma$;
the algorithm terminates once all symbolic events have been
explored. Within each refinement iteration focused on symbolic event
$\msgB{op}{\overline{x}}{\phi}$ that has $\Pi_{h}$ as its history
trace and $\Pi_f$ as its future trace, the algorithm tries to
perform forward (resp., backward) synthesis, if the event is not in
$\Mfw$ (resp., $\Mbw$). Notably, if an operation is generable ($\GEN(\eff{op})$ on line $7$), it is considered to be a \emph{root}, and no
additional backward synthesis needs to be performed.  Instead, the
event is simply added to $\Mbw$ (line $8$). Both the forward and
backward synthesis routines yield a 6-tuple $(\Gamma, \Pi_h, \lastA
\msgA{op}{\overline{x}}, \Pi_f, \Mfw, \Mbw)$.  The refined abstract
trace returned on line $9$ returns concatenation of the history trace,
event, and future trace ($\Pi_h \seqA \lastA \msgA{op}{\overline{x}}
\seqA \Pi_f$ after one or both of the forward or backward synthesis
procedures execute.

\begin{algorithm}[ht!]
% \Params{A 5-tuple $(\Gamma, \Pi_h, \lastA \msgA{op}{\overline{x}}, \Pi_f, \Gchecked)$ that are type context, history, current, and future automata, as well as checked message set.}
% \Output{Set of refined 5-tuples }
\Procedure{$\forward(\Gamma, \Pi_h, \lastA \msg{op}{\phi}, \Pi_f, \Mfw, \Mbw)$}{
  \tcp{Select the \PAT of $\eff{op}$ from handler specification}
    % \SJ{I don't understand this form - the braces at the end are not part of a PAT}
    \If{exists $(\eff{op}, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{H}{\lastA\msg{op}{\phi'}}{F}) \in \Delta$ and $(\eff{op}, B) \in \Sigma$ }{
        $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}$ \tcp*[l]{add ghost variables and parameters types in type context}
      % \tcp{add qualifier of $\eff{op}$ event into type context}
      % \SJ{Didn't we already do this at line 4 in Algorithm 1?}
        $\msg{op}{\phi} \leftarrow \msg{op}{\phi \land \phi'}$ \tcp*[l]{merge current automata} 
        $\Pi_h \leftarrow \Pi_h \land H$ \tcp*[l]{merge history automata} 
        $\Pi_f \leftarrow \Pi_f \land F$ \tcp*[l]{merge prophecy automata}
        \tcp{non-emptiness check}
        \If{$\Gamma \not\vdash (\Pi_h \seqA \lastA\msg{op}{\phi} \seqA \Pi_f) \subseteq \neg\allTL$}{
            \tcp{return type context, property, as well as updated forward and backward set}
            \Return{$(\Gamma', \Pi_h, \lastA \msg{op}{\phi}, \Pi_f, \Mfw \cup \{\eff{op}\}, \Mbw \cup B)$} 
        }
    }
}
\caption{Forward Synthesis}
\label{algo:forward}
\end{algorithm}

\paragraph{Forward and backward synthesis} The forward synthesis subroutine is
shown in \autoref{algo:forward}. It first retrieves the \PAT\ of
operation $\eff{op}$ on line $2$; this handler type also indicates the
children (future) operators of $\eff{op}$, i.e., $B$.  The algorithm
then merges the selected \PAT into the violation property
piecewise. First, the current operation $\eff{op}$ should be aligned
(line $4$), guaranteeing that the input assumed by the violation
property is consistent with the \PAT ($\phi \land \phi'$). Next, the
algorithm merges the existing history trace of the violation property
with the \PAT{}'s history automata on line $5$, and the violation
property's future trace with the \PAT{}'s prophecy automata (line
$6$). In order to guarantee the refined violation property contains at
least one realizable trace, we also need to check for non-emptiness of
the violation property, as previously discussed.  We do so by ensuring
that the violation property $\Pi_h \seqA \lastA\msgA{op}{\overline{x}}
\seqA \Pi_f$ is not empty, as established in the \textsc{WfHAF} rule
in \autoref{fig:selected-typing-rules}.

\begin{algorithm}[ht!]
\Procedure{$\backward(\Gamma, \Pi_h, \lastA \msg{op}{\phi}, \Pi_f, \Mfw, \Mbw)$}{
    \tcp{Select the \PAT of some $\eff{op_{parent}}$ from the handler specification, who sends a message with operator $\eff{op}$}
    \If{$(\eff{op_{parent}}, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{H}{\msg{op_{parent}}{\phi_\Code{parent}}}{F_1 \seqA \lastA \msg{op}{\phi'} \seqA F_2}) \in \Delta$ and $(\eff{op_{parent}}, \{\eff{op}\} \cup B) \in \Sigma$}{
        % \tcp{add qualifier of $\eff{op_{parent}}$ and $\eff{op}$ event into type context}
        $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}$ \tcp*[l]{add ghost variables and parameters types into the type context}
        $\msg{op}{\phi} \leftarrow \msg{op}{\phi \land \phi'}$ \tcp*[l]{merge current automata}
        $\Pi_h \leftarrow \Pi_h \land (H \seqA \lastA \msg{op_{parent}}{\phi_\Code{parent}} \seqA F_1)$ \tcp*[l]{merge history automata}
        $\Pi_f \leftarrow \Pi_f \land F_2$ \tcp*[l]{merge prophecy automata}
        \tcp{non-emptiness check}
        \If{$\Gamma \not\vdash (\Pi_h \seqA \lastA\msg{op}{\phi} \seqA \Pi_f) \subseteq \neg\allTL$}{
            \tcp{return type context, property, as well as updated forward and backward operations set}
            \Return{$(\Gamma', \Pi_h, \lastA \msg{op}{\phi}, \Pi_f, \Mfw \cup \{\eff{op_{parent}}\}, \Mbw \cup \{\eff{op}\} \cup B)$} 
        }
    }
}
\caption{Backward Synthesis}
\label{algo:backward}
\end{algorithm}

The backward synthesis subroutine is shown in \autoref{algo:backward},
which is similar to the forward synthesis procedure but explores
message dependencies from children messages back to a parent. This
reversal in synthesis direction leads to several differences. We pick
an operator $\eff{op_{parent}}$ whose handler will eventually send a
message with operator $\eff{op}$.  The violation property needs to
align the current operator $\eff{op}$ whose message is to be
synthesized with the $\eff{op}$ in the prophecy automata
of $\eff{op_{parent}}$,  as shown below
{\small\begin{align*} \underbrace{ \effL H \effR \effL
    \lastA\msg{op_{parent}}{\phi_\Code{parent}} \effR \effL F_1
  }_\texttt{actual history} \seqA \underbrace{ \lastA \msg{op}{\phi'}
  }_\texttt{actual current } \seqA \underbrace{ F_2 \effR
  }_\texttt{actual prophecy}
\end{align*}}\noindent
which changes the merge procedure (line $4$ - $6$).  Now, the forward
operator set adds the parent operator $\eff{op_{parent}}$, and the
backward set adds $\eff{op}$ to the backward operator set
($\{\eff{op}\} \cup B$).

\begin{example} We demonstrate the refinement of the violation property $\negSCA$ into $\negSCA'$ in our motivating example given
  the following initialized elements:
{\footnotesize\begin{align*}
\Gamma \equiv\;& \Code{x}\hasoty{int}{\top}, \Code{y}\hasoty{int}{\top} \quad \Mfw \equiv \emptyset \quad \Mbw \equiv \emptyset
\\ \Pi \equiv\;& \allTL \seqA \lastA \msg{writeRsp}{v = \Code{x}} \seqA \globalA \neg \msg{writeRsp}{\top} \seqA \lastA\msg{readRsp}{v = \Code{y} \land st = \true \land \Code{y} \not= \Code{x}} \seqA \allTL
\tag{before iteration $1$}
\end{align*}}\noindent

In the first iteration, our algorithm focus on operator
$\eff{readRsp}$. Our algorithm performs forward synthesis since this
message is not recorded in $\Mfw$. As specified by $\Sigma$, no
additional messages are sent by the handler of $\eff{readRsp}$, and
the violation property does not change. Next, we perform backward
synthesis since $\eff{readRsp}$ is not generatable. There are two
types in $\Delta$ whose prophecy automata contains
$\eff{readRsp}$: {\footnotesize\begin{align*}
  &\Code{x}\hasnty{int}\garr \rg{\finalA \msg{writeReq}{v = \Code{x}}
    \land
    \neg\nextA\finalA\msg{writeReq}{\top}}{\lastA\msg{readReq}{\top}}{\finalA\msg{readRsp}{v
      = \Code{x} \land st = \true}} \tag{$\tau_1$} \\& \rg{\neg\finalA
    \msg{writeRsp}{\top}}{\lastA\msg{readReq}{\top}}{\finalA\msg{readRsp}{st
      = \false}} \tag{$\tau_2$}
\end{align*}}\noindent
Type $\tau_2$ constrains the $\eff{readRsp}$ message output by the
this operator's handler to have a \textsf{false} status, which conflicts with the
violation property and thus cannot pass the non-emptiness check. On
the other hand, if we choose $\tau_1$, then we can perform the
following piecewise merge, which leads to the following result:

{\footnotesize\begin{align*}
\Gamma \equiv\;& \Code{x}\hasoty{int}{\top}, \Code{y}\hasoty{int}{\top} \quad \Mfw \equiv \{\eff{readRsp}, \eff{readReq}\} \quad \Mbw \equiv \{\eff{readRsp}\}
\\ \Pi \equiv\;& \allTL \seqA \lastA\msg{writeReq}{v =\Code{y}} \seqA \globalA \neg \msg{writeReq}{\top} \seqA \lastA\msg{readReq}{v = \Code{y}} \seqA \allTL \seqA \lastA\msg{writeRsp}{v = \Code{x}} \seqA
\\& \globalA \neg \msg{writeRsp}{\top} \seqA \lastA\msg{readRsp}{v = \Code{y} \land st = \true \land \Code{y} \not= \Code{x}} \seqA \allTL \tag{after iteration $1$}
\end{align*}}\noindent
which indicates that there is a new symbolic event $\msg{writeReq}{v =\Code{y}}$ that happens before $\msg{readReq}{v =\ \Code{y}}$ in the
trace; the presence of a message for operator $\eff{readReq}$ is required by $\tau_2$, which can now be considered. The remainder of the
refinement steps used to construct a violating trace can be found in \techreport{}.
\end{example}

\begin{theorem}\label{theorem:algo-sound}[Synthesis Algorithm Soundness]
The controller synthesized by the algorithm is type-safe with respect to our declarative typing rules.
\end{theorem}
