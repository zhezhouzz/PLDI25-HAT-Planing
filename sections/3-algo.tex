\section{Synthesis}
\label{sec:synthesis}

When typing a program using our declarative typing rules, we can
freely apply the subsumption rule to align the (ordered) set of events
performed by the program with a \PAT{} that describes a user's desired
high-level property. Any \emph{synthesis} procedure based on such a
high-level specification must devise a similar ordering alongside the
events in the program it generates. At the same time, each event needs
to align with the specification of its operator in $\Delta$, i.e., its
temporal and data-dependency constraints must be satisfied. Our
solution to this problem is a refinement loop, depicted in
\autoref{fig:intuition-algo}, that iteratively refines the high-level
specification into one that is consistent with these constraints. Each
iteration of this loop targets a single event, adding events before
and after that event so that its dependences are satisfied, i.e., so
that the corresponding operator at that point in the synthesized
program is well-typed. Our loop also employs an regex non-emptiness
check to ensure it represents a generator that produces at least one
feasible trace. After the refinement loop has finished, a
corresponding well-typed generator program can be mechanically
extracted from the refined property.

\subsection{Abstract trace}

Our algorithm normalizes the SRE within global property and all operator \PAT into a set of \emph{abstract traces}, a sequence of events
$\msg{op}{\phi}$ and kleene stars. This normal form makes it easy to identify
the traces that must precede and follow each event $\msg{op}{\phi}$ in
an SRE.

\begin{definition}[Abstract Trace] An abstract trace $\Pi$ is a SRE without union and top-level Kleene star, defined by the following grammar: %
  {\small
    \begin{alignat*}{2}
      \text{\textbf{Abstract Trace}}& \quad &\Pi  ::= \quad & \epsilon ~|~ se ~|~ \Pi \seqA \Pi ~|~  A^*
    \end{alignat*}} \noindent
\end{definition}

The global property \ref{prop:stlc} is an abstract trace. Every SRE can be normalized into a finite set of abstract traces.\footnote{The definition of both the SRE normalization procedure is provided in the \techreport{}.}

\subsection{Synthesis Algorithm}

\setlength{\textfloatsep}{4pt}
\begin{algorithm}[t!]
  \Params{Ghost variables $\overline{x{:}b}$, operator context
    $\Delta$, and abstract trace $\Pi$}%
  \Output{Generator $e$, such that
    $\Gamma; \Delta; \emptyset \vdash e:\rg{\epsilon}{\Pi}{\epsilon}$} %
  $\Gamma \leftarrow \overline{x{:}\rawnuot{b}{\top}}$; $M \leftarrow \emptyset$
  \tcp*[l]{initialize type context and dependency map}
$(\Gamma, \Pi, M) \leftarrow \refine(\Gamma, M, \Pi)$ \tcp*[l]{refine events}
% $(\Gamma, \Pi) \leftarrow \synRec(\Gamma, M, \Pi)$ \tcp*[l]{synthesize loop}
\Return{$\derive(\Gamma, M, \Pi)$} \tcp*[l]{synthesize recursions and derive generator program}
\Procedure{$\refine(\Gamma, M, \Pi)$}{
  \While(\tcp*[h]{an event that needs to be refined}){exists $\msg{op}{\phi}$ s.t. $\Pi = \Pi_h \seqA \msg{op}{\phi} \seqA \Pi_f$}{
    \If(\tcp*[h]{the events triggered by $\msg{op}{\phi}$ is not examined}){$\eff{op} \not\in \textbf{Dom}(M)$}{
        $(\Gamma, M, \Pi) \leftarrow \forward(\Delta, \Gamma, M, \Pi_h, \msg{op}{\phi}, \Pi_f)$
    }
    \If(\tcp*[h]{the event that triggers $\msg{op}{\phi}$ is not examined}){$\eff{op} \not\in \textbf{Codom}(M) \land \OBS(\eff{op})$}{
        $(\Gamma, M, \Pi) \leftarrow \backward(\Delta,\Gamma,M, \Pi_h, \msg{op}{\phi}, \Pi_f)$
    }
  }
  \Return{$(\Gamma, M, \Pi)$}
}
\caption{Synthesis}
\label{algo:top-syn}
\end{algorithm}

Our top-level synthesis algorithm is shown in \autoref{algo:top-syn}.
Given an abstract trace $\Pi$ and corresponding ghost
variables as input, this nondeterministic algorithm synthesizes a well-typed
$\DSL{}$ generator. The algorithm follows the structure given in
\autoref{fig:intuition-algo}, using a refinement loop (lines $4$ -
$10$) to refine the input abstract trace $\Pi$, and then deriving the final (recursive) generator from the refined property (line $9$). Each iteration of this loop nondeterministically chooses
a target event that is used to refine the current abstract trace (line $5$) to preform forward or backward refinement until all events are resolved.
Different choices may result in different event orders, and some of
these choices may cause the algorithm to fail.  Our implementation
resolves this nondeterminism in the algorithm via an efficient
backtracking search procedure that takes the union of all successful
runs in order to capture different orderings.

\paragraph{Event dependencies}
The refined abstract trace produced by our loop must be consistent with the operator context, as defined in Definition~\ref{lemma:trace-conistency}.
The events that will
precede and follow each event are not known until the loop is finished,
so we cannot simply track the set of observable events, as the
declarative typing rules did via $\Theta$.
 Instead, each iteration of
the loop detects the unresolved dependencies of a target event in the
current abstract trace and repairs them by inserting appropriate
events before and after it. Intuitively, each observable event
$\eff{op_{child}}$ must follow an operation $\eff{op_{parent}}$, whose operator semantics produces it.
The algorithm maintains a dependency map $M$ that records the associated child events for each resolved parent event; i.e., $M[\eff{op_{parent}}] = \{\overline{\eff{op_{child}}}\}$, refining the candidate
abstract trace into one that satisfies this dependency map.\footnote{ To enable $M$ to distinguish distinct
occurrences of events with the same effect operator in the abstract
trace, we tag each occurence of an operator with a unique
identifier.

\paragraph{Trace refinement loop} Depdenecy map $M$ is empty (line $1$) when synthesis starts, and the type context consists
of ghost variables whose qualifiers are $\top$ (line $1$).
At each iteration of $\refine$, the algorithm selects a symbolic event $\msg{op}{\phi}$ from the current abstract trace $\Pi$ for refinement. The trace $\Pi$ is partitioned into history ($\Pi_h$) and future ($\Pi_f$) traces surrounding the target event.
Resolving the dependencies of $\msg{op}{\phi}$ requires us to insert events that must precede it and
events that must follow it; the former treats it as a child operation and constitutes the \emph{backward}
synthesis phase, while the latter treats it as a parent and is subsumed by a
\emph{forward} synthesis pass.
Concretely, if the event is not in the domain of $M$, forward synthesis is invoked to introduce necessary child events following it (line $6$). Conversely, if an observable event is not in the codomain of $M$, backward synthesis is applied to introduce its parent event preceding it (line $8$). Both synthesis procedures return an updated triple $(\Gamma, M, \Pi)$, reflecting the revised type context, dependency map, and abstract trace. The refinement loop terminates when all events are refined.

\setlength{\textfloatsep}{4pt}
\begin{algorithm}[t!]
\Procedure{$\forward(\Delta, \Gamma, M, \Pi_h, \msg{op}{\phi}, \Pi_f)$}{
    $(\Theta, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{\Pi_h'}{\msg{op}{\phi'}}{\Pi_f'}) \in \Delta(\eff{op})$\tcp*[l]{select \PAT of $\eff{op}$ from operator context}
    $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}$ \tcp*[l]{add ghost variables and parameters types to type context}
    $\msg{op}{\phi} \leftarrow \msg{op}{\phi \land \phi'}$ \tcp*[l]{merge current regex}
    $\Pi_h \leftarrow \Pi_h \land \Pi_h'$; $\;\;\Pi_f \leftarrow \Pi_f \land \Pi_f'$ \tcp*[l]{merge history and prophecy regex}
    \If(\tcp*[h]{non-emptiness check}){$\Gamma \vdash \Pi_h \seqA \msg{op}{\phi} \seqA \Pi_f \not \subseteq \emptyset$}{
        \Return{$(\Gamma, M \cup [\eff{op} \mapsto \Theta], \Pi_h \seqA \msg{op}{\phi} \seqA \Pi_f)$}\;
    }
}
\Procedure{$\backward(\Delta, \Gamma, M, \Pi_h, \msg{op}{\phi}, \Pi_f)$}{
    \tcp{Choose an $\eff{op_{parent}}$ that creates capability $\eff{op}$ and retrieve its \PAT{}}
    $(\Theta, \overline{z{:}b}\garr\overline{y{:}t}\sarr\rg{\Pi_h'}{\msg{op_{parent}}{\phi_{parent}}}{\Pi_{f_1}' \seqA \msg{op}{\phi'} \seqA \Pi_{f_2}'}) \in \Delta(\eff{op_{parent}})$ where $\eff{op} \in \Theta$\;
    % $() = \Pi_f'$ \tcp*[l]{The prophecy regex of $\eff{op_{parent}}$ must contains $\eff{op}$}
    $\Gamma \leftarrow \Gamma, \overline{z{:}\rawnuot{b}{\top}}, \overline{y{:}t}$ \tcp*[l]{add ghost variables and parameters types to type context}
    $\msg{op}{\phi} \leftarrow \msg{op}{\phi \land \phi'}$ \tcp*[l]{merge current regex}
    $\Pi_h \leftarrow \Pi_h \land (\Pi_h' \seqA \msg{op_{parent}}{\phi_{parent}} \seqA \Pi_{f_1}')$; $\;\Pi_f \leftarrow \Pi_f \land \Pi_{f_2}'$ \tcp*[l]{merge history and prophecy regex}
    \If(\tcp*[h]{non-emptiness check}){$\Gamma \vdash \Pi_h \seqA \msg{op_{parent}}{\phi_{parent}} \seqA \Pi_f \not \subseteq \emptyset$}{
        \Return{$(\Gamma, M \cup [\eff{op_{parent}} \mapsto \Theta], \Pi_h \seqA \msg{op_{parent}}{\phi_{parent}} \seqA \Pi_f)$}\;
    }
}
\caption{Forward and Backward Synthesis}
\label{algo:forward-backward}
\end{algorithm}

\paragraph{Forward and backward synthesis} The forward synthesis
subroutine is shown in \autoref{algo:forward-backward}. It first retrieves the
capability and \PAT{} of the target operation $\eff{op}$ from $\Delta$ (line $2$).
The algorithm then merges the selected \PAT
into the global property piecewise by aligning the target operation (line $4$) and merging the corresponding history and prophecy regex (line $5$).
% First, the occurence of the
% target operation in the current abstract trace $\eff{op}$ is aligned
% with its \PAT{} in $\Delta$ (line $4$). Next, the algorithm
% merges the history and future traces with the \PAT{}'s history and
% prophecy regex (lines $5$).
Before returned the refined result (line $7$), the algorithm checks for non-emptiness to ensure that the refined abstract trace can derive a generator program (line $6$).



The backward synthesis subroutine, shown in \autoref{algo:forward-backward},
is similar to the forward synthesis procedure but works backward from a
target event.
%  insert preceding events into $\Pi_h$ to resolve parent
% dependencies.
The change in direction results in several differences
with its forward counterpart. The procedure now selects a parent
operator $\eff{op_{parent}}$ whose capability includes the target operator $\eff{op}$, so does its prophecy regex (line $9$). The abstract trace needs to align the target operator $\eff{op}$
with its counterpart in the prophecy regex of $\eff{op_{parent}}$:
\vspace{-.4cm} \par\nobreak {\footnotesize %
  \begin{align*} \underbrace{ \effL \Pi_h \effR \effL
    \msg{op_{parent}}{\phi_\Code{parent}} \effR \effL \Pi_{f_1}'
    }_\texttt{actual history} \seqA \underbrace{
    \msg{op}{\phi'} }_\texttt{actual current } \seqA \underbrace{
    \Pi_{f_2}' \effR }_\texttt{actual prophecy}
  \end{align*}}\noindent
This is reflected in how the two are merged (line $11$ - $12$). Finally, $\eff{op_{parent}} \mapsto \Theta$ is added to the dependency map (line $14$).

\subsection{Synthesis Recursion}
\label{subsec:synthesis-recursion}

\setlength{\textfloatsep}{4pt}
\begin{algorithm}[t!]
\Procedure{$\derive(\Gamma, \Pi)$}{
  \If(\tcp*[h]{Synthesize sequential program}){$\Code{(*)}$}{
    \lForEach(\tcp*[h]{remove Kleene star}){$A^* \in \Pi$}{
      $\Pi \leftarrow \Pi[A^* \mapsto \epsilon]$
    }
    \Return{$\compile(\Gamma, \Pi)$} \tcp*[l]{compile term}
  }
  \Else(\tcp*[h]{Synthesize recursion}){
        $f_T, (\Pi_h, \Pi_{\Code{rec}}, \Pi_f) \leftarrow \mathbf{MatchTemplate}(\Pi)$\;
        $(\Gamma \cup \Gamma_{\Code{rec}}, \_, \Pi_h \seqA \textcolor{orange}{\Pi_{\Code{rec}}'} \seqA \Pi_f) \leftarrow \refine(\Gamma, M, \Pi_h \seqA \textcolor{orange}{\Pi_{\Code{rec}}} \seqA \Pi_f)$ \tcp*[l]{only refine $A$}
        $f_\Code{rec} \leftarrow f_T[\derive(\Gamma_{\Code{rec}}, \Pi_{\Code{rec}}')]$ \tcp*[l]{derive recursion}
        $e_h, e_f \leftarrow \derive(\Gamma, \Pi_h), \derive(\Gamma, \Pi_f)$ \tcp*[l]{derive history and future}
        \lIf{$\Gamma;\Delta;\emptyset \vdash (f_\Code{rec}\;0):\rg{\Pi_h}{\Pi'}{\Pi_f}$}{
          \Return{$e_h;(f_\Code{rec}\;0);e_f$}
        }
  }
}
\caption{Synthesis Recursion}
\label{algo:syn-recursion}
\end{algorithm}

The Kleene stars within the abstract trace can be treated as placeholders for recursion.
As illustrated in \autoref{algo:syn-recursion}, the algorithm non-deterministically chooses either to synthesize a sequential program by dropping the Kleene stars on (lines 2 - 4)\footnote{The definition of $\compile$ is straitforward and provided in the \techreport{}.}, or to synthesize a recursive function call (lines 5-10) at the position of the Kleene star. We adopt a template-based approach to synthesize the recursion, where $\S{MatchTemplate}$ returns a template function $f_T$ whose body is waiting to be filled, along with the abstract trace of the recursion body ($\Pi_{\Code{rec}}$), and the corresponding history and future abstract traces ($\Pi_h$ and $\Pi_f$). The algorithm then invokes $\refine$ and $\derive$ on these traces to fill in the body of the recursion (lines 5--6). The final program is constructed by combining the resulting previous and subsequent programs ($e_h$ and $e_f$), derived from the history and future abstract traces (line 9). Before returning this combined program, the algorithm needs to sanity-check that the synthesized recursion is well-typed (line 10), ensuring that the refined abstract trace $\Pi_{\Code{rec}}'$ is indeed the inductive invariant of the recursion.

\begin{example}[Recursion Template]
One template we consider is non-deterministic loop, which has template function $f_T$ as $\mykw{fix} f.\lambda x. () \oplus (\square; f (x + 1))$, which can be matched with any Kleene star $A^*$ in the abstract trace. Other templates we consider are provided in the \techreport{}.
\end{example}

\begin{theorem}[Synthesis is Sound]
  \label{theorem:algo-sound}
  The generator synthesized by the algorithm is type-safe with
  respect to our declarative typing rules.
\end{theorem}
