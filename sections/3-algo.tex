\section{Synthesis}
\label{sec:synthesis}

\begin{figure}[ht!]
  \centering
  \includegraphics[width=0.84\linewidth]{figures/syn-gen.drawio.png}
  \caption{The intuition of test generator synthesis.}
  \label{fig:syn-gen}
\end{figure}

When typing a program using our declarative typing rules, we can
freely apply the subsumption rule to align the (ordered) set of events
performed by the program with a \tyName{} that describes a user's desired
high-level property. Any \emph{synthesis} procedure based on such a
high-level specification must devise a similar ordering alongside the
events in the program it generates. At the same time, each event needs
to align with the specification of its operator in $\Delta$, i.e., its
temporal and data-dependency constraints must be satisfied. Our
solution to this problem is a refinement loop, depicted in
\autoref{fig:syn-gen}, that iteratively refines the high-level
specification into one that is consistent with these constraints. Each
iteration of this loop targets a single event, adding events before
and after that event so that its dependences are satisfied, i.e., so
that the corresponding operator at that point in the synthesized
program is well-typed. Our loop also employs an regex non-emptiness
check to ensure it represents a generator that produces at least one
feasible trace. After the refinement loop has finished, a
corresponding well-typed generator program can be mechanically
extracted from the refined property.

\subsection{Abstract trace}

Our algorithm normalizes the SRE within global property and all operator \tyName into a set of \emph{abstract traces}, a sequence of events
$\msg{op}{\phi}$ and kleene stars. This normal form makes it easy to identify
the traces that must precede and follow each event $\msg{op}{\phi}$ in
an SRE.

\begin{definition}[Abstract Trace] An abstract trace $\Pi$ is a SRE without union and top-level Kleene star, defined by the following grammar: %
  {
    \begin{alignat*}{2}
      \text{\textbf{Abstract Trace}} \quad \Pi  ::= \quad & \epsilon ~|~ se ~|~ \Pi \seqA \Pi ~|~  A^*
    \end{alignat*}} \noindent
Every SRE can be normalized into a finite set of abstract traces.\footnote{The definition of both the SRE normalization procedure is provided in the \techreport{}.}
\end{definition}

\begin{example}[Potential Violation of Read Atomicity]
Assume the user want to test if the read atomicity property is violated by the suituation that the last state of database is not consistent with the last observed state from client via a read response. This property can be expressed as the following abstract trace with a ghost variable $x$:
\begin{align*}
  \allA \msg{writeRsp}{v \not= x}(\anyA \setminus \msgC{writeRsp})^* \msg{readRsp}{v = x} \tag{$\Pi_\Code{RA}$}\label{prop:global}
\end{align*}
\end{example}

\subsection{Synthesis Algorithm}

\setlength{\textfloatsep}{4pt}
\begin{algorithm}[t!]
  \Params{Ghost variables $\overline{x{:}b}$, operator context
    $\Delta$, and abstract trace $\Pi$}%
  \Output{Generator $e$, such that
    $\Gamma \vdash e : \uhat{\epsilon}{\Unit}{\Pi'} \land \Gamma \vdash \Pi' \subseteq \Pi$} %
  $\Gamma \leftarrow \overline{x{:}\urt{b}{\top}}$
  \tcp*[l]{initialize type context and dependency map}
$(\Gamma, \Pi) \leftarrow \refine(\Gamma, \Pi)$ \tcp*[l]{refine events}
% $(\Gamma, \Pi) \leftarrow \synRec(\Gamma, M, \Pi)$ \tcp*[l]{synthesize loop}
\Return{$\derive(\Gamma, \Pi)$} \tcp*[l]{synthesize recursions and derive generator program}
\Procedure{$\refine(\Gamma, \Pi)$}{
  \While(\tcp*[h]{an event that needs to be refined}){exists $\msg{op}{\phi}$ s.t. $\Pi = \Pi_h \seqA \msg{op}{\phi} \seqA \Pi_f$}{
    \lIf{$\GEN(\eff{op})$}{
        $(\Gamma, \Pi) \leftarrow \forward(\Delta, \Gamma, \Pi_h, \msg{op}{\phi}, \Pi_f)$
    }
    \lElse{
        $(\Gamma, \Pi) \leftarrow \backward(\Delta,\Gamma, \Pi_h, \msg{op}{\phi}, \Pi_f)$
    }
  }
  \Return{$(\Gamma, \Pi)$}
}
\caption{Synthesis}
\label{algo:top-syn}
\end{algorithm}

Our top-level synthesis algorithm is shown in \autoref{algo:top-syn}.
Given an abstract trace $\Pi$ and corresponding ghost
variables as input, this nondeterministic algorithm synthesizes a well-typed
$\DSL{}$ generator. The algorithm follows the structure given in
\autoref{fig:syn-gen}, using a refinement loop (lines $4$ -
$10$) to refine the input abstract trace $\Pi$, and then deriving the final (recursive) generator from the refined property (line $9$). Each iteration of this loop nondeterministically chooses
a target event that is used to refine the current abstract trace (line $5$) to preform forward or backward refinement until all events are resolved.
Different choices may result in different event orders, and some of
these choices may cause the algorithm to fail.  Our implementation
resolves this nondeterminism in the algorithm via an efficient
backtracking search procedure that takes the union of all successful
runs in order to capture different orderings.

\paragraph{Event dependencies}
The refined abstract trace produced by our loop must be consistent with the operator context.
The events that will
precede and follow each event are not known until the loop is finished, e.g., a $\eff{readReq}$ event means that is a $\eff{readRsp}$ event that follows it, vice versa.
Thus, we cannot simply parse the abstract trace from left to right to find the dependencies.
Instead, each iteration of
the loop detects the unresolved dependencies of a target event in the
current abstract trace and repairs them by inserting appropriate
events before and after it. Intuitively, each observable event
$\eff{op_{rsp}}$ must follow an operation $\eff{op_{req}}$, whose operator semantics produces it.\footnote{ To enable $M$ to distinguish distinct
occurrences of events with the same effect operator in the abstract
trace, we tag each occurence of an operator with a unique
identifier.

\paragraph{Trace refinement loop} The type context is initialized with a set of ghost variables whose underapproximated qualifiers are $\top$ (line $1$).
At each iteration of $\refine$, the algorithm selects a symbolic event $\msg{op}{\phi}$ from the current abstract trace $\Pi$ for refinement. The trace $\Pi$ is partitioned into history ($\Pi_h$) and future ($\Pi_f$) traces surrounding the target event.
% Resolving the dependencies of $\msg{op}{\phi}$ requires us to insert events that must precede it and
% events that must follow it; the former treats it as a child operation and constitutes the \emph{backward}
% synthesis phase, while the latter treats it as a parent and is subsumed by a
% \emph{forward} synthesis pass.
If the event $\msg{op}{\phi}$ is generatable, forward synthesis is invoked to introduce necessary response events following it (line $6$). Conversely, backward synthesis is applied on the observable event to introduce its request event preceding it (line $8$). Both synthesis procedures return an updated pair $(\Gamma, \Pi)$, reflecting the revised type context and abstract trace. The refinement loop terminates when all events are refined.

  $\Gamma \leftarrow \Gamma, \overline{z{:}\urt{b}{\top}}, \overline{y{:}\widehat{t_y}}, x{:}t_x$ \tcp*[l]{add ghost variables and parameters types to type context}

We illustrate one iteration of the refinement process for \autoref{prop:global}. The refinement loop begins with the following initial state:
\vspace{-.4cm} \par\nobreak {\footnotesize %
\begin{align*}
  \Gamma \equiv\; x{:}\urt{\Int}{\top} \quad M \equiv \emptyset \quad
  \Pi \equiv\; \allA \msg{writeRsp}{v \not= x}(\anyA \setminus \msgC{writeRsp})^* \textcolor{blue}{\msg{readRsp}{v = x}}
  \tag{before iteration $1$}
\end{align*}}\noindent
Assume the first iteration targets the observable event $\msg{readRsp}{v = x}$ (colored blue). The algorithm invokes backward synthesis to locate the corresponding request event (i.e., $\eff{readReq}$) in history. The retrieved type of $\eff{readRsp}$ is shown below, which requires that there is a write response event and read request event that has happened before:
\vspace{-.4cm} \par\nobreak{\footnotesize %
\begin{align*}
  i{:}\Int\sarr x{:}\Int\sarr \uhat{\allA\msg{writeRsp}{i\;x}(\anyA \setminus \msgC{writeRsp})^* \msgA{readReq}{i}\allA}{\Unit}{\msgA{readRsp}{i\;x}}
\end{align*}}\noindent
During the merging of abstract traces, the algorithm finds that the $\msg{writeRsp}{i\;x}$ event in the type cannot be aligned with the $\msg{writeRsp}{v \not= x}$ event, nor inserted between it and $\msg{readRsp}{v = x}$ in the abstract trace, since they have conflicting qualifiers, which will be rejected by the non-emptiness check. \vspace{-.4cm} \par\nobreak{\footnotesize %
\begin{align*}

  \\&\Pi \equiv\; \allA\textcolor{DeepGreen}{\msgA{writeRsp}{i\;x}} (\anyA \setminus \msgC{writeRsp})^* \textcolor{DeepGreen}{\msgA{readReq}{i}} \allA \msg{writeRsp}{v \not= x}(\anyA \setminus \msgC{writeRsp})^*  \msgA{readRsp}{i\;x}
\end{align*}}\noindent
\end{example}

Kleene stars ($A^*$) in abstract traces are interpreted as recursion points. The synthesis algorithm $\derive$ non-deterministically either (i) generates a sequential program by eliminating the Kleene stars (lines 2--4)\footnote{The definition of $\derive$ is provided in the \techreport{}.}, or (ii) synthesizes a recursive program by expanding the Kleene star using recursion. We employ a template-based strategy, in which algorithm match the given abstract trace with a template $T$, together with abstract traces for the recursion body ($\Pi_{\Code{rec}}$), as well as its associated history ($\Pi_h$) and future ($\Pi_f$) traces. According to \textsc{TFixInd}, the algorithm unrolls the recursive body up to a bounded depth and invokes $\refine$ to ensure that the unrolled abstract traces are well-typed. The synthesized programs for these three traces are then composed to instantiate the placeholders in the recursive template.

\begin{example}[Recursion Template]
A representative template is a non-deterministic loop, whose form is $T = \boxed{e_\Code{h}};\zlet{f}{\mykw{fix}\ f.\lambda ().\ \boxed{e_\Code{rec}};\ (()\oplus f())}{f\;()};\boxed{e_\Code{f}}$, allowing $A^*$ in the abstract trace to be matched. For instance, consider the refinement of the abstract trace $\Pi_\Code{RA}$:
{\small\begin{align*}
  &\Pi_\Code{refined} \equiv\; \underbrace{\epsilon}_\text{history trace} \underbrace{\allA}_\text{placeholder of previous iterations} \underbrace{\msgA{writeReq}{i\;x}\allA\msgA{writeRsp}{i\;x} ... \msgA{readRsp}{i\;x}}_\text{one iteration of recursion} \underbrace{\epsilon}_\text{future trace}
\end{align*}}\noindent
Here, $\Pi_\Code{refined}$ corresponds to the traces generated by a single recursion iteration in Example~\ref{ex:read-atomicity}. The template thus assigns $\Pi_{\Code{rec}} = \Pi_\Code{refined}$, with $\Pi_h$ and $\Pi_f$ as empty traces (i.e., $\epsilon$). The synthesizer refines the abstract trace for $i$-fold recursion unrolling (i.e., $\Pi_h\Pi_{\Code{rec}} \ldots \Pi_{\Code{rec}}\Pi_f$) to guarantee that multiple unfoldings remain well-typed. The final recursive program is assembled by composing synthesized programs from these traces to populate the template placeholders, thereby yielding exactly the recursive function in Example~\ref{ex:read-atomicity}.
\end{example}

\begin{theorem}[Synthesis is Sound]
  \label{theorem:algo-sound}
  The generator synthesized by the algorithm is type-safe with
  respect to our declarative typing rules.
\end{theorem}
