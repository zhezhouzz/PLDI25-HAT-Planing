 Benchmark & Model description & Property to be violated & synthetic fault \\

 \midrule
\textsf{Database} & The simplified database used as the running example in \autoref{sec:overview} & \textbf{RWY}: Read-Your-Writes policy described in \autoref{sec:overview}  & Remove atomicity check \\
\midrule
\textsf{EspressoMachine} & The user interacts with a coffee machine
                           through its control panel, where the panel must correctly interpret user inputs and handler errors from coffee machine. & \textbf{Strong Consistency}: The user, panel, and underline coffee machine should have a consistent view of the state of the machine. Precisely, if the coffee machine is in a state ``run out of water'', the user should get notification.  & Remove error forwarding in panel machine \\
\midrule
\textsf{Simplified2PC} & A simplified version of a two-phase commit protocol (2PC), where we assume transactions have a single update operation.  & \textbf{RYW}: Read-Your-Writes policy & Original implementation doesn't guarantee RYW \\
\midrule
\textsf{HeartBeat} & A failure detector that sends heartbeat messages
                     to a node to make sure it is alive; it reports
                     an error only when the node doesn't reply for
                     multiple rounds, taking into account network packet
                     lost. & \textbf{Eventual Consistency}: The node and detector should have the same view of state of node (alive or crashed) eventually. Precisely, if the node is alive, the detector will not report a false positive error. & Specify a timer-based protocol that can cause a false positive error. \\
\midrule
\textsf{BankServer} & The user interacts with a bank to withdraw money from their accounts, where the balance is stored in another database component. & \textbf{Strong Consistency}: The bank and underline store should have consistent view of balance of accounts. Precisely, bank should disallows users from withdraw an amount greater than their current balance. & remove negative balance check in bank machine \\
\midrule
\textsf{RingLeaderElection} & Ring election algorithm where a group nodes are interconnected in a ring-like structure.  & \textbf{Unique leader policy:} there can only be an unique node that announces itself as leader. & Remove node comparison as introduced in \autoref{sec:impl}. \\
\midrule
\textsf{Firewall} & A set of internal and external nodes communicating
                    through a firewall. Firewall should block message from an external node, unless this node has received message from internal nodes previously. The firewall actually keep a whitelist of external nodes that can communicate with internal nodes. & \textbf{Liveness:} if a internal node sends a message to an external node, it will be eventually able communicate with external node. & modify the whitelist updating logic.  \\
\midrule
\textsf{ChainReplication} & Chain replication protocol\cite{RS04}. & \textbf{RYW:} Read-Your-Writes policy. & Remove log recover procedure after node crash  \\
\midrule
\textsf{Paxos} & Paxos protocol\cite{Lam02a}. & \textbf{Unique leader policy:} there are multiple proposers are accepted as leaders. This will additionally violates the Paxos agreement policy, i.e., not two distinct learners can learn different values. & A wrong node comparison in leader election \\
\midrule
\textsf{Raft} & Raft algorithm\cite{OO14}. & \textbf{Strong Consistency:} the consistency of leader's view and committed data, i.e., if a log entry is committed, then it should also be present in the leader's log. & Remove log recover procedure after node crash\\
\midrule
\textsf{Anno2PCModel} & Case study in \autoref{sec:impl} & \textbf{Strong Consistency:} the user and the database in 2PC should have the same will view of stored data, as explained in  the case study in \autoref{sec:impl} & Remove buffered transaction update operation  \\
\bottomrule
